We qualified the existing Xuzhou HySpex and WHU-Hi HongHu products for a restricted two-class development comparison. Xuzhou is a delivered 436-column product formed from HySpex VNIR and SWIR observations, whereas HongHu contains 270 processed columns from a Headwall Nano-Hyperspec acquisition. Their published nominal ground sampling distances are 0.73 m and approximately 0.043 m, respectively. The delivered arrays and role records were authenticated through the existing curator and release chain. For the local derived Xuzhou product, agreement among the original class table, product descriptions, image and label fingerprints, and historical per-ID counts supports a corroborated development mapping; it does not establish byte identity with the publisher's original conversion. [Xuzhou product](https://www.3sobs.cn/share), [WHU-Hi provider](https://rsidea.whu.edu.cn/e-resource_WHUHi_sharing.htm).

The common targets are exposed bare ground and tree canopy. Published Xuzhou labels 1 and 7 are grouped as bare ground and label 6 as tree canopy; the corresponding HongHu labels are 3 and 22. These are explicit coarse label groups rather than matched materials or species. Original unannotated values are excluded. In particular, common target 0 denotes mapped, originally labeled ground and does not convert raw unannotated 0 into a supervised class.

Each scene retains five original fitting labels and five exposed development labels per common class. The two scenes therefore contain 40 unique labeled centers: 20 fitting and 20 development observations. Reversing source and target roles reuses these identities. The selected fitting and development observations occupy 7 and 3 original parents in Xuzhou and 5 and 2 in HongHu. Parents and observation boxes do not overlap across the selected roles; the minimum excluded-axis box gap is four pixels. An independent metadata join showed that HongHu's five development labels in each class occupy only one parent per class. Parent identifiers describe the original release geometry and are not authenticated independent parcels or acquisition replicates.

The existing reader returns 7×7 patches clipped to their authorized original tile, with replicated boundary values. No cross-tile halo or whole-scene graph is introduced. Original per-scene development-training normalization statistics are preserved; their historical unlabeled footprint is broader than the selected common-class fitting centers. The raw numerical branch precedes this project normalization but follows the original product preprocessing. Samplewise features and features using scene statistics are therefore reported separately, with their actual target-data access identified.

The baseline implementation specifies eight fixed spectral-distribution features and a binary linear model with nine coefficients, together with a deterministic class-centroid reference. Its engineering checks cover gradients, numerical references, checkpoint restoration, role restrictions, independent feature and metric reconstruction, and deidentified exports. These checks establish implementation behavior on generated examples. Real baseline fitting and classification evaluation remain paused, so no real transfer accuracy or efficacy result is attributed to this implementation.
