We propose a development comparison between the existing Xuzhou HySpex product and the original public HyRANK Hyperion training images Dioni and Loukia. The candidate target groups are annotation-defined inland water and woody cover. The proposed Xuzhou source values are 2 and 6. HyRANK's published class ordinals suggest Water and the three forest groups, but their delivered numeric values and semantic scope must first be bound to the original release. These groups are a new annotation coarsening, not the established Xuzhou–HongHu ground/canopy task.

The primary ordered comparisons would be Xuzhou→Dioni and Dioni→Xuzhou. Dioni↔Loukia would provide a same-instrument cross-scene reference, while each scene's fitting-to-development evaluation would provide a matched local reference. Additional Xuzhou↔Loukia cells would assess sensitivity to the selected Hyperion scene. These nine cells reuse three source models per initialization seed; they are not nine independent datasets. All source models would use the same eight-feature descriptor, nine-coefficient linear classifier, 64 fixed updates and roots 64, 512 and 2048. Each source endpoint would be fitted in an isolated scene-specific stage from fresh initialization and frozen before evaluation arrays are opened. No external pretrained weights, target population normalization, target-specific optimizer updates or target-validation selection would be allowed within a transfer arm.

Both primary directions would be assessed separately against the balanced constant predictor and their matched local reference, using all fixed seeds and the same target observations. The descriptive signal rule is mean accuracy above 0.5 and mean negative log-likelihood below log(2); it is not a significance or independent-generalization claim. Per-class denominators, confusion, paired correctness changes and losses would accompany initialization variation and explicitly limited parent-resampling sensitivity. Missing original metadata, insufficient class support or incompatible spatial roles would block execution rather than trigger an automatic change of scene, class mapping or update budget.
