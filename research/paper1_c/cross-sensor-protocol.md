# Cross-sensor paper: feasibility before routing experiments

Provisional English title: **Coverage-Aware Selective Computation for Few-Shot Hyperspectral Transfer across Sensors**.

The question is whether delivered spectral coverage improves the decision to invoke a full classifier beyond information already available from a light classifier, at the same target-label budget and full-model call rate. This is a separate paper from within-region residual decomposition. No new training, target calibration labels or confirmation labels are authorized by this proposal.

## Dynamic computation and sensing are different axes

The supplied Montello et al. review is *A survey on dynamic neural networks: From computer vision to multi-modal sensor fusion*, Image and Vision Computing 170 (2026), 105980, DOI [10.1016/j.imavis.2026.105980](https://doi.org/10.1016/j.imavis.2026.105980). The exact supplied PDF is pinned by SHA-256 in the read-only inventory. Its taxonomy and Fig. 3 separate adaptive output, computation graph and input. A lazy light/full classifier cascade changes the computation graph. An intermediate exit in one backbone changes the output location. Removing observed bands changes the input and is a separate experimental intervention. A soft fusion weight after computing both branches does not demonstrate skipped computation.

The review discusses fusion of information from multiple sensors observing an environment. Our present inputs are one HSI acquisition at a time, transferred between devices/scenes. Different band counts do not create simultaneous multimodal fusion. The current assets cannot support an HSI+RGB/SAR/LiDAR fusion claim: no aligned, jointly released second modality and independent label roles have been established. The review motivates hypotheses and measurements; it is not evidence that a coverage router works here.

## Equal-budget routing matrix to register after admission

Freeze identical light/full weights, released labels, actual observed bands, model/support/spatial seeds and update/selection schedules across these six arms: fixed-light, fixed-full, content-only router, content+coverage router, coverage-permuted router, and a random router matched to the frozen full-call quota. Use source-only pseudo-target development for a source-generalization policy; keep target few-shot adaptation as a separately labeled experiment with its full K+V+calibration annotation budget.

The content and content+coverage routers must have the same capacity (constant/zero coverage channels in the content arm), optimization and decision budgets. Permute coverage within the preregistered scene/observation strata without changing masks or pixel inputs; retain a mismatched-coverage diagnostic separately. At a fixed call rate, random routing uses a frozen local RNG and matched quotas, with repeated random assignments reported separately from independently trained models. Prefer deploying one genuinely cheap model and lazily invoking the heavy path for selected complete blocks; do not score the full path first and then discard its output.

Calibration, architecture selection and confirmation need distinct custodian-approved roles. Existing V5 points selected base checkpoints and have been used in development; reusing them can describe development routing but cannot prove independent safety. WP11's blocked confirmation labels remain blocked. The first future executable contract must bind source checkpoint hashes, real lightweight checkpoint quality, router inputs and fitting labels, chosen threshold/call quotas, host/UUID, full-class order, source/target adaptation costs and output locations. It must not open sealed query merely to complete this table.

Report device-by-device OA/AA/Kappa/macro-F1 and all class recalls, Xuzhou IDs5/6 individually, HongHu classes with ≤25 training labels and class21 separately; no averaging away failed devices. Count real full-model invocations and actually skipped graph construction. Measure patch/block input, light model, coverage extraction, routing, preprocessing/Q/A, synchronization, transfer and heavy execution; retain p50/p95 end-to-end latency and warm/cold conditions. Include source pretraining, target adaptation, router calibration and every failed run in cost records. Existing WP05/06/11 outputs can supply frozen model and protocol evidence within their original contracts; they do not establish a new independent device experiment by themselves.

The immediate paper gap is not an extra mechanism: it is trustworthy device/version/coverage binding, more than one independent acquisition per device where a device effect is claimed, a defensible semantic task, a genuinely lazy cheap path and independently released calibration/confirmation roles. These gaps are explicit stopping conditions for formal cross-device conclusions; the bounded external-baseline pilot remains useful development work while they are unresolved.
