# WP10 低秩 TensorLy 源码核查与冻结对照

关联 #265、#425、#427，研究主计划 WP10 与实施 §19.11。

## 源码与复用边界

Denton 等的卷积低秩压缩和 Jaderberg 等的低秩展开提供近似拟合与同条件成本比较的依据。WP10 的首层 CNN `point_conv` 是 128×64 矩阵，原实现把输出展开为两个实际的 1×1 卷积，右因子无 bias，原 bias 仅在左因子，两核间无激活。其 FP64 截断 SVD 以奇异值平方根分配尺度。[Denton 等](https://arxiv.org/abs/1404.0736) [Jaderberg 等](https://arxiv.org/abs/1405.3866)

TensorLy 论文对应作者维护的 TensorLy 核心。TensorLy-Torch 是 TensorLy 组织提供的 PyTorch 工具。LXC 获取两者官方 Git 源码并固定版本。两者均为 BSD 3-Clause，许可分别在 `LICENSE` 与 `LICENSE.txt`，本包使用范围为下列核查和隔离环境的核心库调用，未引入上游训练、配置或数据。[TensorLy 论文](https://arxiv.org/abs/1610.09555) [TensorLy-Torch 固定提交](https://github.com/tensorly/torch/tree/25c915d554476d62dfc80c91de8e50fcd3d13542) [TensorLy 核心 0.9.0](https://github.com/tensorly/tensorly/tree/7401f09e05812a0c4c3d673bbaf8419acd7b33b7)

- TensorLy-Torch `25c915d554476d62dfc80c91de8e50fcd3d13542`。核对 `FactorizedConv.from_conv`、`_get_factorized_conv`、`convNd` 和张量化线性调用。现有卷积支持恢复稠密核或执行 CP、Tucker、TT，空间/核心因子及运算次序与 WP10 两核不同。本包对它做源码与测试入口核查，无 TensorLy-Torch 运行结果。许可 SHA-256 `bf22aafda22fa9ec54a6244d16ceb12b0ef90b049afd5b81a35828653657fd1b`。[卷积派发源码](https://github.com/tensorly/torch/blob/25c915d554476d62dfc80c91de8e50fcd3d13542/tltorch/functional/convolution.py) [卷积层入口](https://github.com/tensorly/torch/blob/25c915d554476d62dfc80c91de8e50fcd3d13542/tltorch/factorized_layers/factorized_convolution.py)
- TensorLy 核心 `7401f09e05812a0c4c3d673bbaf8419acd7b33b7`。只显式使用 `tensorly.tenalg.svd.truncated_svd`，在本地线程的 NumPy 后端对 CPU FP64 矩阵调用完整 thin SVD，再取前 r 组。NumPy 参考共享该后端，另用 Gram 矩阵谱、重建残差和 native PyTorch FP64 路径核对。许可 SHA-256 `cec6658b73e4d53db122b72acd39971846fb331f7efe8fcd317e0cf9f6207ab5`。[SVD 源码](https://github.com/tensorly/tensorly/blob/7401f09e05812a0c4c3d673bbaf8419acd7b33b7/tensorly/tenalg/svd.py) [NumPy 后端](https://github.com/tensorly/tensorly/blob/7401f09e05812a0c4c3d673bbaf8419acd7b33b7/tensorly/backend/numpy_backend.py)

`compression/low_rank_tensorly.py` 由实验入口显式构造。依赖缺失、版本错误、Git 提交错误、安装 Python 源文件字节或模块路径错误均拒绝。分解产生的两因子写回原 `LowRankMatrix` 结构，保存格式、回读验证、生产前向和原有恢复入口沿用现有实现。TensorLy 仅参与离线初始化，CPU 和 CUDA 推理读取原生检查点，现有生产默认仍为完整 FP32。

## 冻结开发块和稠密源零恢复对照

原模型生产提交 `01b99515156694b09c250723b89277f475700897`，冻结部署提交 `2e5807e46d1c37163fbe8aed4fe54cd62eed139c`。在原部署提交独立认证清单，核对候选中的冻结运行路径字节、权重、侧车及角色输入。按原 5 块 3,920 像素前向和固定 K5/V5 的 9 类×5 个标签计算三头指标。18 个已选包来自同一个原始模型、三组恢复种子 64/512/2048；原有每轨 178 步、总 6,408 次更新仅作追溯。本次 CPU 逐位匹配 270 个三头块概率哈希，预测、混淆矩阵和三头指标均与原审计一致。三个恢复种子均没有三头保护同时通过的减参 SVD。

另从 WP08 off 原稠密选中状态（第 246 步，预算 256）产生本次十个零恢复候选，保留原稠密、r8/r16/r32/r64 和随机 r16。同秩四组的 PyTorch 和 TensorLy 在 CPU 端五块三头概率逐位一致，所有与同秩原生的逐类保护一致。r64 与原稠密最大绝对概率差 5.96×10⁻⁸，增加了 4,096 个参数。r8/r16/r32 的 FP64 截断尾部 Frobenius 范数分别为 5.55121/4.65655/3.03208；两种路径回存 FP32 左右矩阵的残差均符合门槛。对原稠密结果继承 OA/AA 0.5pp、逐类召回 0.5pp 与小类新增错误 0 的门槛，本批小类覆盖全部 9 类。

## 成本
