## 交付内容与用途

M4 不再只提供独立算子：骨干在共享去噪、一次 Q/A 构造之后，统一调用分解并进入现有两阶段调度。CNN 按模式接收变换输入，Graph 使用原 clean X 的区域表示 Z；普通与交互路径都经过同一接入点。主动模式聚合一次并复用 Z，默认关闭时保留原调用路径、参数键/数量和初始化序列。

共享配置新增 `model.region_residual_mode`，旧多数据集 CLI 新增 `--region-residual-mode`，支持 none/capacity_control/x_residual/residual_only/x_region。严格空间及 G3 开发训练复用配置建模入口，已验证实际训练、优化器更新、保存恢复及已完成实验跳过。现有侧车自动保存并重建模式；旧侧车缺字段时恢复为 none，旧原始权重仍要求显式架构。参数相同的 x_residual/x_region 也不能静默混作源/目标架构，G3 迁移现显式拒绝模式不一致。

新字段参与新配置/运行身份；原有运行文件和哈希未重写。旧真实实验仍能在新代码下核验和加载。未修改既有实验 JSON、损失、采样、预算、选模、融合及 M4-A 分解数学；未新增优化器/RNG 断点续训能力。诊断按需返回标量，中间残差数组不自动导出。原始无 M4 的默认模型与启用 M4 的研究模型分别接受验证。

## 首轮 GPU 数值比较问题及处理

首轮唯一失败发生在关闭模式下与旧实现成对比较 GPU FP32 梯度，位置含 `backbone.HGNN_Branch.hgc1.weight`。三次“当前实现对当前实现”的 FP32 对照也超出原容差：前向差异约 1.8e-7～2.7e-7，部分图分支偏置梯度差异最高约 3.3e-5；另三次父/当前出现同量级现象。两次 FP64 父/当前探针前向差异低于 3.4e-16，梯度检查通过。诊断支持重复计算数值波动，不能据首轮失败直接认定新增路径改变了算法。

最终只调整本模块拥有的兼容性测试：保留 FP32 初始化与 GPU 前向比较，成对 GPU 梯度/缓冲用 FP64、收紧为 rtol=1e-9/atol=1e-10；CPU FP32 则强化为精确相等。其他 GPU 训练、真实数据及生产精度/内核/优化器均未改，未放宽旧套件容差。首轮失败及 8 组诊断 JSON 保留，最终提交完整重验通过。
