## CUDA 低秩与保护

冻结范围仍为徐州同五块、3,920 像素，三恢复种子各自的 dense/r16 六包。CPU 参考每包只做一次读后推理，完整三头哈希与原归档逐字节相同。因此 CUDA 能直接逐元素核对，免用原 GT、query 或重新校准。实际运行提交 `e6a652e9466ca7ca1cb5455e7e19a258b80b5fc3`。

同一自然边界读取八张卡。GPU 0 和 GPU 3 当时符合 12,288 MiB 空闲、利用率 ≤60% 的推理测量门槛。使用较低利用率的 GPU 3，物理 UUID `GPU-2cbff259-d7db-32cf-b267-8f296e34b1d5`，RTX 4090。持共享锁后再次核对该 UUID，准入为 14,852 MiB 空闲、58% 利用率。每个工作进程只见这一物理 UUID，CUDA 地址为 `cuda:0`。推理使用 WP11 的确定性图算术，关闭 TF32。此许可适用于冻结推理，P4 继续按它自己的原登记设备和资源门槛执行。

每包八次暖态、两次预热和三次新重载首回。新重载首回为同进程中新载模型后的第一请求，模型加载及参数传输另记。历史 CPU 冷启动为新进程到可验证输出，保留原范围。每次实测含读取已批准的观察、验证与解码、同步输入传输、原生逐块构图和网络、同步输出传回及三头哈希。CUDA 构图与前向剩余时间使用同一事件时钟。六包暖态中位输入传输 1.81–3.16 ms，构图 149.41–196.95 ms，前向余部 52.45–62.79 ms，结果传回 0.62–0.75 ms。暖态顺序吞吐 14,253–16,509 像素/秒。暖态 PyTorch 进程峰值分配 129,650,688 字节、峰值保留 148,897,792 字节。LXC 的 `nvidia-smi` 未返回可归属该工作进程的显存读数，该列留空。

独立复核三头 6,985,440 个首回和暖态概率值，按原 `1e-6 + 1e-5 × |CPU|`，最大绝对差 3.28e−7，超限与改判均为零。六包完整 CUDA 概率哈希均有差异。全部像素的类别结果一致，允许复用同一 V5 45 点、九类的原逐类结果与小类保护；三组请求 r16 的保护执行实际走本种子 dense，并核对完整三头输出。种子 512 的 r16 p95 较慢，种子 64、2048 较快，保留原稠密默认。新 CUDA 路径实际执行 FP32，原 CPU 整数权重与 oneDNN 包不搬到 CUDA。三值归档为打包解码后浮点，GPU 低比特没有合格内核证据。

## CPU oneDNN 与原 FP32

复用已获批的 QAT 五块、相同 3,920 像素和同预算 `fp32`／`qat-first`。使用已验证的 TorchAO 0.15 固定 Git 树与原 oneDNN 整数包。FP32 暖态 p50/p95 为 385.39/406.29 ms，`qat-first` 为 389.05/412.07 ms。同样的重新读包到三头输出窗口，新重载首回 p50/p95 分别为 387.17/421.50 和 397.58/412.18 ms。每次分派检查实际记录五次 `onednn::qconv2d_pointwise`。U8/S8 运算后的输出反量化为浮点，原图和其他网络仍为 FP32。

计算完整输出的哈希并与各自原 CPU 独审比对，二者均逐字节相同。单层 `qat-first` 的原三头与逐类保护通过，显式请求执行 oneDNN。双层 `qat-both` 的原保护拒绝，实际执行同预算 FP32 并核对三头输出。当前尾延迟仍以实际值报告。此比较沿用 QAT 恢复预算。低秩与 QAT、WP11 固定路径及旧 CUDA 常驻的不同训练或计时范围单列，WP12 不合并收益。
