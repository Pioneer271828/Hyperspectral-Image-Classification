# WP12 已验证解码观测的暖态复用

## 目的与范围

承接主计划 §22 和实施计划 §19.13。既有三景端到端受控测量显示暖态请求的已分段开销主要来自观测读取和解码。上一次真实 sealed-mmap 配对未能在 PaviaU 超过原波动门槛，保留 buffered 默认。这一包只试验明确选用的进程内解码复用。三个场景名称对应既有合成工程夹具的形状和观测格式，用来覆盖部署规模。候选选择依据此前已有的观测加载分段，而非 #505 的封存结果或跨批时间差。 [既有观测 I/O 验收](WP12_封存观测读取归因与合成冷暖配对_20261121.md)

每个 worker 缓存一份输入。第一次把来源固定为许可目录内的正规文件，用原已封存快照验证归档 SHA-256，再用 PyTorch 的只权重 CPU 解码和原张量摘要核对。缓存只接受六个无标签观测字段，保留自有 CPU 存储，并分别把归档和张量存储限制在 600 MiB。暖态命中在复制前后核对来源设备号、inode、大小、mtime 和 ctime。返回的密集张量和稀疏 COO 各有独立存储，可以在一次请求中改变而不污染后续请求。命中不重新读取整个归档。来源被替换、删除、改写或改成符号链接时退出，下一输入须开启新会话以重新验证。

本次只在原工程入口显式开启 `--compare-decoded-cache`。同设备的原 buffered 与候选各保留一个模型常驻进程。每景先暖身两次，再进行 12 对请求，6 对 AB、6 对 BA，比较观察读取到主机三头判决的时延。暖身首回承担验真、解码、私有化和首次复制，单独记录。现有生产部署加载及默认不变。

## 验收结果

六个批次共 72 对暖态请求（144 次）和 24 次暖身。同设备两臂的观测归档、解码张量、三头分数与判决散列逐次一致。跨设备的三组判决散列也一致。独立脚本重算每对时序、AB/BA、队列顺序、缓存首回／命中、阶段合计、请求分位数及内存门槛。GPU 三景均达到既有暖态工程判据，CPU 仅 PaviaU 达到。

| 设备与场景 | buffered → 缓存 P50 / P95（ms） | 配对节省 P50（ms） | 缓存更快 | RSS 变化（MiB） | 工程门槛 |
|---|---|---:|---:|---:|---|
| GPU 3 PaviaU | 658.02 / 748.96 → 170.43 / 237.82 | 496.92 | 12/12 | +13.20 | 通过 |
| GPU 3 徐州 | 931.93 / 1002.17 → 251.39 / 381.12 | 650.85 | 12/12 | −18.39 | 通过 |
| GPU 3 洪湖 | 2631.67 / 2783.46 → 627.87 / 721.78 | 1999.01 | 12/12 | +14.60 | 通过 |
| CPU PaviaU | 5787.49 / 6239.80 → 5342.45 / 5460.65 | 507.05 | 12/12 | +140.14 | 通过 |
| CPU 徐州 | 11508.04 / 14670.10 → 10772.31 / 14633.28 | 756.69 | 11/12 | +153.57 | 节省小于 3860.97 ms 波动门槛 |
| CPU 洪湖 | 25755.02 / 25945.19 → 23678.84 / 23810.66 | 2050.47 | 12/12 | +524.99 | RSS 超出 256 MiB 增量门槛 |

GPU 三景的读取和解码合计 P50 分别从 543.20、765.87、2283.55 ms 降到 78.81、107.90、320.23 ms。三景 GPU 峰值分配逐景保持在 717.62、2051.71、1869.05 MiB。缓存实际保留约 157.79、226.23、547.07 MiB 的 CPU 张量。GPU 候选首次暖身耗时分别为 1.63、1.96、3.68 秒，该开销未计入暖态命中。峰值 RSS 含进程其他内存，缓存存储量与 RSS 不直接相加。经验 P95 来自 12 个样本，共享负载可能影响波动。

仓库检查通过，6 个相关测试文件独立发现 26 项，24 通过、2 跳过、0 失败。新增 4 项覆盖密集和稀疏 COO 副本隔离、替换或改写输入拒绝、归档 SHA、监督字段及大小限制。旧封存快照测试通过。真实数据、真实训练、封存标签和新冷启动测量均为零。真实 GPU 暖态配对仍需单独放行，CPU 负项保留，原 buffered 路径继续为生产默认。
