# E4-G4G：目标支持训练、校准选模与冻结特征恢复验收

Issue #159 / Draft PR #160。训练与正式验收提交 **b29f7b9f1a99c1245d593dcd167404d3f953d450**，分支 `codex/issue-159-target-training`，标签 `module-e4g4g-target-short-v1`。这是一项目标训练链路工程验收，尚非完整迁移精度实验。原模型、旧入口、默认结构、损失与联合选模规则保持。

## 用途与隔离

新增 `target_data_context.py`、`target_training.py`、`scripts/train_target_short.py`。每个留出方向使用 G4P1 的仅另外两个源训练的模型，全新目标分类头和域状态；比较从头训练、完整微调、仅训练新头。目标图为 G4D 的无标签 SLIC/超图，禁止旧目标1%标签 LDA 图。没有假设三个数据集的数值类别共享语义。

K=10/class 加独立 V=5/class，支持种子64，模型种子64，头种子1064。本轮 PaviaU/Xuzhou 分别90训练+45验证标签，HongHu220+110；训练入口只接收释放的索引/标签，不读取 query 标签。支持 API 同时允许 K1/5/10；完整支持集重复与其他K实验尚待开展。完整场景无标签上下文与归一化/校准明确属于传导协议，不是严格空间留出或零目标输入 DG。旧G3不变。

每组12更新，验证发生在1/4/7/10/12步。仍使用原三头概率损失、类别平衡、Adam及学习率。新协议以**校准后的融合验证NLL最小值、相同值取最早**选模，NLL同时驱动原调度器；真实OA另记，没有把负NLL冒充OA。配置中的 `primary_checkpoint=val_loss` 与实际行为一致。只新增可选runtime hooks；旧runtime不提供时走原路径，源训练状态等价测试及全量回归通过。

所有方法先计算全场景骨干，再在进入既有线性头前选择监督行。CPU FP64 独立全图掩码损失/全参数梯度对照通过，未改变监督数学语义；原生FP32不同矩阵形状/归约顺序仍可能有数值差异。仅新头方法先做全部BN总体校准，然后冻结骨干参数与运行模式，持久化少量支持/验证特征；manifest绑定骨干、观测、行和实际payload文件。首次轨迹记录manifest哈希，断点恢复先核对既有已发布训练状态再读取缓存，禁止悄悄重算另一份FP32特征。

完整微调和从头训练每次验证在原始固定状态上生成独立校准clone，不改变原优化器续训状态。仅新头方法验证时核验骨干确实冻结且未改变，复用初始BN统计并明确重绑定当前分类头/原始状态，不反复重算BN导致缓存失配。保存模型绑定原始状态文件、精确观测与图；重载后重新设置冻结标记。缓存构建与初次校准时间单列，不将缓存称为结构剪枝或部署加速。
