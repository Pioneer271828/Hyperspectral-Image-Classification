## 复现中发现并处理的测试问题

初轮提交 `f0dc577bad402d572fe06d88ab3de9c8f5a639c9` 的台账入口、5 项专项和 206 项 CPU 回归通过，但 GPU 上旧 G3“修复前后训练权重接近”测试偶发失败，位置为 `backbone.CNN_Branch.0.point_conv.weight`。这说明之前单次通过不能保证该比较稳定，不把初轮写成验收成功。

尝试确定性 CUDA 诊断时，当前环境明确报 `adaptive_avg_pool2d_backward_cuda` 无确定性实现；仅作测试探针的 CPU pooling 替代也没有建立可靠的 GPU 参数相等结论。探针、错误和失败运行均保留，没有把这些设置带进训练实现。

最终将**这一项跨实现的数值中立证明固定为单线程 CPU**，损失与权重从原容差比较加强为严格相等；独立 CPU 探针连续 3 次通过。其余 5 项 provenance 测试继续在原生 CUDA/Adam 验证实际源/目标/开发训练、配置、采样、权重和恢复。没有放宽阈值，也没有声称独立 GPU 重算必须逐位相同。此范围调整已在 Issue #70 登记，只改 `tests/test_run_provenance.py` 及交付核对器的允许路径。
