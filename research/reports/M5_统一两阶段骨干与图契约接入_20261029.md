# M5：统一两阶段骨干与图契约接入

关联 [Issue #15](https://github.com/Pioneer271828/Hyperspectral-Image-Classification/issues/15)、[PR #16](https://github.com/Pioneer271828/Hyperspectral-Image-Classification/pull/16)，基于 M3 PR #14。本轮仅交付 M5，完成后暂停评审。

## 实现及用途

普通与插件模型统一为一套 `forward_stages` 调度：CNN/图第一阶段 → 可选一次消息交换 → 可选边更新 → 第二阶段。新增 `cnn_stage1/2`、`graph_stage1/2` 方法，保留原 ModuleList/HGNN 参数名、64→128→64 宽度、卷积核 3/5、归一化、三头监督和原固定融合。第一阶段使用 A0，第二阶段使用可选更新后的 A1。

M3 GraphState 已接入 learned 构图，保留旧 graph_info 正则键；可在多/单数据集 forward 注入手工图。历史 static Q/A 继续兼容，不强加新 GraphState 的行归一化约束。显式 graph_assignment_mode / graph_adjacency_mode 接入 C0 JSON、旧训练 CLI、checkpoint 导出/恢复；已有 checkpoint 缺字段时使用原 learned/learned 默认。

CNN 阶段输入和区域输入独立，后续 M4 可在统一调度前变换 CNN 输入，减少只接到一条路径的风险。本轮只验证该入口在消息关闭/开启时生效，未实现 M4 残差机制，也未添加诊断分类器、额外深度或新损失。接口详见 [骨干指南](../../docs/guides/backbone-stages.md)。

## 兼容与阶段验证

首轮 **78/78** 测试通过（原 71 + 新增 7；测试本体 6.425 秒），CPU/CUDA smoke 通过。

从基准 Git 提取旧 VCASAHGCN 模块，与新骨干对照：3 种 norm（group_norm/domain_bn/batch_norm）× static/learned × 5 组插件（无、gated、graph 更新、gated+joint、零强度 gated）× 两个数据集/波段数 B12/17，共 60 组。输出、输入及所有参数梯度在预设容差内一致；参数键、参数量与 BN 缓冲严格一致。输出容差 rtol=1e-5/atol=1e-6，梯度 rtol=2e-4/atol=2e-6。

新增还覆盖四阶段顺序/形状和各执行一次、独立 CNN 输入 × 消息开关四组合、GraphState 注入绕过构图且正则保留梯度、固定 Q/A 控制的分类梯度边界、配置指纹和实际 CLI、新旧侧车恢复、历史非行归一化 static A 兼容。图控制只在明确指定时生效，默认 learned 算法与训练策略保持原行为。

## GPU 真实训练闭环

PaviaU，K64/embed32、显式 group_norm，tile32/gap2/split_seed2026，训练块统计，原三头监督与图正则，val_loss 选模。三个工程配置均 epochs=0、每轮两步，沿用原含端点循环语义，合计六次优化。

| 配置 | 归属/图边权 | 插件 | 优化次数 | 完成/恢复 |
|---|---|---|---:|---|
| m5_spatial_plain | learned/learned | 无 | 2 | completed / skipped |
| m5_spatial_fixed_q | fixed_grid/learned | 无 | 2 | completed / skipped |
| m5_spatial_joint | learned/learned | gated + joint | 2 | completed / skipped |

每组四个阶段各调用 84 次（训练 2 + 验证 41 + 选模恢复后测试 41），每阶段都记录到两次有限非零梯度。CNN 第一/二阶段为 N×128/N×64，图第一/二阶段为 M×128/M×64；实际块 N=448 或 784、M=12 或 16，包含边缘块。验证选模后的 checkpoint 成功恢复，控制字段一致；再次运行验证产物后 skipped，禁止创建优化器的断言通过。

三组共享固定 plan_hash `edb778be5ec7e8a8d00d666ca860fbbb2e9ca1bb3c7cd662e7db2ad80d59fa21` 和 statistics_hash `c188d202de330eb839bbe552cf8dba7a2839298a6cc8a91341aa51052ef7e9c7`。测试区缺 3/7 类，如实保留，没有依据目标标签重抽。

训练进程 PyTorch 峰值 allocated 42,101,248 bytes、reserved 56,623,104 bytes；不包含另一项目及独立 smoke 子进程，也不作为完整训练显存或速度基准。三组只是两步闭环检查，不产生模式精度优劣、收敛或跨传感器结论。
