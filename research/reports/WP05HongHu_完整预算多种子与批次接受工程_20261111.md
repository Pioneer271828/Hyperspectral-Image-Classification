## 执行、恢复与接受

`transfer.p4_full_budget_campaign` 提供 `prepare`、`run`、`accept`，协调器在隔离进程中调用 `worker`。登记与执行目录分别固定，配对内五组分配至同一物理卡。2 卡每卡 60 例，3 卡每卡 40 例。每个 GPU 子进程只看见登记 UUID 对应的逻辑 `cuda:0`。每次操作在协调器和子进程各检查一次显存至少 12,288 MiB、利用率至多 60%。协调器持有批次及独占卡锁，工作进程核对继承的两个锁。无资源返回可恢复的等待状态，失败停止后续派发并保存日志。已接受案例直接核对凭据。未绑定更新凭据的 checkpoint 会停止并保留供诊断。

CPU 和 CUDA 分别绑定数值协议。同一案例恢复核对代码、scope、案例身份、权重加载摘要、设备和运行环境，恢复 CPU/CUDA RNG、Adam 和调度器状态。CUDA 使用严格确定性 FP32、关闭 TF32，并固定 cuBLAS 工作区。PyTorch 2.7.1 的 CUDA 自适应平均池化反向拒绝严格模式，单独替换池化后原稀疏乘路径仍出现选中概率重载不精确。正式 CUDA worker 对这两种运算使用同一组自适应窗口均值与 COO 行加权和，限定在登记的 CUDA 数值上下文中。旧模型及 CPU 入口继续使用原算子。恢复与选中态验收仍要求同卡逐位一致。

逐例接受核对 1,500 步轨迹、验证事件与选步、学习率、Adam moments 和调度状态、图梯度与参数变化、每个已授权训练点的曝光。使用原始概率和授权标签独立复算三头及逐类指标。初态、选中态和末态均输出固定 train/devval 拟合。选中态另外记录七种冻结观测条件及图摘要。非选中验证事件核对登记时间和选模历史，独立概率重放次数为 0。总接受要求 120 个案例和 24 个完整配对、每例完成态恢复 0 更新，以及所有输入、调用与审计文件指纹匹配。

未来单次完整批次含 180,000 更新和 6,000 次计划验证。还包括每例完成后的选中态重载、完成态 0 更新检查及冻结诊断。旧真实 CPU 短测的每例 24 步调用均值为 16.56 秒，完成态重载均值为 12.86 秒。用差值分摊估算约 0.154 秒/步，按 180,000 步约 7.7 CPU 小时。用含启动、哈希和验证的毛耗时分摊约 0.69 秒/步，对应约 34.5 CPU 小时。两值仅为外推参照，长序列存储、50 次验证、缓存和各案例 tile 分布都会改变耗时。

## 正式批次命令

以下为主对话审查生产准入后使用的命令。应在与登记 SHA 一致且干净的 LXC checkout 执行。当前登记中的两卡和三卡 UUID 来自真实设备清单，用于静态分派检查。生产登记需要使用当时可用的 UUID。另建登记时需使用新目录，并保留登记输出的完整 scope 文件 SHA256。

```bash
base=/home/lbx/hsi-pioneer271828
python="$base/envs/hsi/bin/python"
runs="$base/runs"
sha=e6d628c18b4adab48ece2d9c077eef724fe4f2c8
parent="$runs/wp05-honghu-paired-exposure-short01/registration.json"
prior="$runs/wp05-honghu-paired-exposure-independent01/receipt.json"
registration="$runs/<新登记目录>"
production="$runs/<新执行目录>"
export PYTHONDONTWRITEBYTECODE=1 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
test "$(git rev-parse HEAD)" = "$sha" && test -z "$(git status --porcelain)"
"$python" -m transfer.p4_full_budget_campaign prepare \
  --expected-commit "$sha" --parent "$parent" --prior-receipt "$prior" \
  --protocol cuda_deterministic_fp32_v1 --gpus "$gpu_uuid_1" "$gpu_uuid_2" "$gpu_uuid_3" \
  --out "$registration"
scope="$registration/scope.json"
scope_sha=$(sha256sum "$scope" | cut -d' ' -f1)
"$python" -m transfer.p4_full_budget_campaign run \
  --expected-commit "$sha" --scope "$scope" --scope-sha256 "$scope_sha" --out "$production"
# 等待资源时，用同一 scope 和执行目录续接。
"$python" -m transfer.p4_full_budget_campaign run --resume \
  --expected-commit "$sha" --scope "$scope" --scope-sha256 "$scope_sha" --out "$production"
"$python" -m transfer.p4_full_budget_campaign accept \
  --expected-commit "$sha" --scope "$scope" --scope-sha256 "$scope_sha" --out "$production"
```

CPU 登记使用 `--protocol cpu_fp32_v1` 并省略 `--gpus`。协调器支持 `--segment` 对同一案例按已提交更新边界续接。资源等待时可用同目录继续，记录失败时保留现场诊断。通过全矩阵校验后，`accept` 才写入 `acceptance.json`。
