# 两景独立确认的最小发布

沿用[独立空间与光学准入](independent-optical-intake.md)和[外部配对头入口](native-paired-head-admission.md)。发布持有人提供实际文件、完整 SHA-256 和用途权限。以下是填写示例，类别数和评价分母用于核对，块号、权限文件、位置和哈希由持有人从已获许可的发布填入。

| 发布项目 | 徐州示例 | 洪湖示例 |
| --- | --- | --- |
| 影像与列顺序 | `500×260×436` 的原发布影像版本、影像头和本地转换链 | `940×475×270` 的完整 WHU-Hi-HongHu、指定交付版本及本地转换链 |
| 类别身份 | 9 个本地数字 ID、持有人确认的正式 ID 与类别表；注明作者图例顺序和本地旧名称不一致的判定 | 22 个完整类 ID；核对作者表 3、15/21 和本地完整类顺序，登记是否曾裁切或重编号 |
| 实际标签/空间 | 已认证 support、calibration、evaluation 块清单及父块缓冲，评价每类至少 20，最低 180 个已发布点 | 三角色及父块缓冲，评价每类至少 20，最低 440 个已发布点；注明 21 类是否有多个可比较块和合法对象边界标签 |
| 波段校准 | 与实际 436 列逐项绑定的波长中心、FWHM/SRF、列保留映射、测量/估算标记与单位 | 与实际 270 列逐项绑定的飞行校准或交付表、相同测量/估算标记与单位 |
| 可复核性 | 同冻结模型、同支持和有序评价点；声明准许的相邻删带和等量分散视图 | 同预算、同初始化、同三角色；先用全带检查类别错误，再记录批准的保留列 |
| 权限 | 独立用途明确列出分类、成本和冻结诊断。真实优化使用单独文件 | 同左；历史选择用点维持原开发角色 |

最小清单采用现有 `wp02_independent_development_intake_v1` 格式。其 `candidate` 提供 Bank 发布和注册两份哈希及精确定义；`roles` 按原发布的块号分别列出 `support`、`calibration`、`evaluation`；`minimum_buffer` 来自持有人确定的实际空间保护；`history` 逐项绑定须排除重叠的历史 Bank。单独用途批准绑定清单 SHA-256、历史 Bank SHA-256 和各用途的布尔值。校准、语义和转换链按引用文件交付，物理与类解释限制跟随实际可核字段。默认允许消费的开发视图以发布回执为准。

分类的三个状态分别输出。获得独立分类许可并有已发布点即可给描述性指标。所有类别至少 20 点时，按原保护门槛评价差值。通过事前保护与目标净改判，且由真实用途授权的正式比较才可标记合格。成本资格由成本许可独立确定，输入只走观测接口。冻结旧开发数据只能提供历史诊断。

如发布可用于几何评价，在同一清单附上 `spatial_annotations` 路径和 SHA-256，在持有人批准附上相同的 `spatial_annotations_sha256`。附件使用 `wp02_released_spatial_annotations_v1`，绑定 Bank、角色登记哈希、来源 SHA-256 及 `evaluation` 块。每块提供有界类别网格、已知几何布尔掩膜和持有人窄结构掩膜。WP12 校对实际发布点标签，用已知几何计算 E0 一像素边界；认证内部需要四邻均有观测。缺附件或缺某块几何时相应分层无认证观测。各分层分别检查每类 20 点条件，成本入口只消费观测。
