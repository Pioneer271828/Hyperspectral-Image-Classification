# 三景光学与独立数据交接

## 光学记录

持有人先固定实际交付版影像与导出顺序，再提交逐列中心表。附上采集日期、仪器型号及序列或定标批次、原始头文件或标定表、发布版本、来源文件 SHA-256、使用条款和辐射单位。带号从头文件或处理记录追到交付列，列出原探测器完整轴和有记录的移除带。如果交付有重采样或拼接，需另附足以解释输入到输出关系的处理记录，并先确认现有一对一格式能表达该版本。

`transfer/wp02_sensor_sidecar.py` 接收两个来自授权目录的固定文件。光学清单 `wp02_optical_sidecar_v1` 绑定场景、仪器、Bank SHA-256、原波段指纹和来源文件。其 `columns` 按已交付顺序列出 `delivered_id`、`detector_id`、`center`。同时提供原始 `detector_axis`、`removed_detector_ids` 和物理单位 `nm` 或 `um`，以及同单位的逐带 `fwhm` 和有序归一化 `srf`。FWHM 或 SRF 无实测表时填 `null`。审批 `wp02_optical_authority_v1` 由持有人另行签发，绑定清单和 Bank 的确切 SHA-256、场景及 `read_only_optical_metadata` 用途。项目从获授权的通道接收审批文件的可信校验值。

通过 `admit` 后，`OpticalAdmission.view` 对现有授权观测签发独立元数据视图，保留交付列号与同一观测字节。物理值统一转成 nm。来源或审批版本变化会改变波段指纹及可用于缓存绑定的标识。该接口保留探测器映射和 SRF 供审计，当前光谱适配器的观测输入仍采用中心和可用的 FWHM。真实项目在收到可绑定的逐带校准前继续使用现有近似轴。

## 独立支持、校准与评估

以每个场景的实际数据版本为单位，请发布持有人提供以下清单。相同支持应用于每组模型及其配对对照。独立地区、独立支持种子和配对模型种子各有自己的身份。

| 材料 | 需要提供的内容 |
| --- | --- |
| 源身份和授权 | 数据与标签来源、确切版本和校验值、允许的标签使用和再分发边界、角色及用途审批 |
| 空间清单 | 同一原场景几何坐标系、块和父块边界、样本 ID 和原类别、最小缓冲、已打开历史区域及标签身份 |
| 支持 | 仅用于训练或拟合的 K 和逐类样本，保留小类并登记支持种子 |
| 校准 | 未用来训练或历史选模的单独块，用于已经登记的校准目的 |
| 评估 | 未曝光、未选模、未用来校准的单独块及逐类有效分母 |
| 保护 | 标签和坐标留在持有人或授权 LXC；交付哈希、角色覆盖、聚合计数及授权的去身份评估结果 |

`transfer/native_independent_release.py` 以 `wp02_independent_development_intake_v1` 清单和单独的 `wp02_independent_development_approval_v1` 审批校验上述角色。审批绑定清单和审查使用的历史 Bank SHA-256，并逐项记录 `independent_accuracy`、`cost`、`frozen_diagnostics`。入库处理器在角色重叠、历史曝光、缓冲不足、标签缺失或用途未授权时拒绝对应消费。三景现有 Bank 的开发支持与开发评估已进入历史证据，且缺少独立校准。洪湖现有划分还触发独立缓冲检查。

在授权容器内，`scripts/run_wp12_retained_acceptance.py engineer` 生成可重现的合成范例。输出包含 `holder-fixture/manifest.json`、`holder-fixture/approval.json`、光学清单及其独立审批。示例均为合成数据；真实审批需要持有人重新签发。
